How PHP runs

PHP is a server-side language. Your browser never sees PHP code; it only sees what PHP echos. A PHP question is two files: an HTML form that collects numbers and a .php file that the form sends them to.

index.htmlForm<input name="students"> … user clicks Submit
HTTP POSTData travelsstudents=10&slices=3 sent to process.php
process.phpPHP runs$_POST["students"] → "10" → calculate
BrowserNew pageshows only the echoed text

Notice that the browser goes to a new page. That is why PHP doesn’t need global “memory” the way JS does: each submit is a fresh, one-shot calculation.

JS habits that break PHP
  • "a" + "b" in PHP tries to add numbers. Use "a" . "b".
  • Forgetting $ → “Undefined constant”.
  • Forgetting ; → “syntax error, unexpected …” on the next line.
  • "\n" doesn’t create a new line in the browser. Use <br>.
  • It’s elseif (one word) or else if. Both work in PHP.

Is casting required?

PHP converts numeric strings automatically in maths ("10" * 3 is 30), so code without (int) usually still works. The lecture casts anyway: it’s safer, and examiners like seeing it.

round() is a trap

round(3.2) is 3, but 3 pizzas can’t feed 3.2 pizzas’ worth of people. Whenever you “can’t order a fraction”, use ceil().

ceil() returns a float. echo ceil(3.75) prints 4, so it looks the same.
