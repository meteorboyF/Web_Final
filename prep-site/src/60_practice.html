If there are more than 6 walks and the goal isn’t reached, show “Try longer walks!”.

Sample: 2000, 4500, 3000 → Total 9500, Average 3166.67, Longest 4500, Almost there!

Tech store orders

SUM of expression · BETWEEN · HAVING alias · CASE

Database tech_store, table orders.

  1. Each customer’s total spending (Qty × UnitPrice), highest first.
  2. Orders whose value (Qty × UnitPrice) is between 3,000 and 40,000 inclusive.
  3. Raise UnitPrice by 5% for Monitor orders from Dhaka.
  4. Cities whose total revenue is above 30,000, highest first.
  5. Every order labelled ‘Big Order’ if its value is at least 20,000, else ‘Small Order’.
@@table orders OrderID|Customer|Product|Qty|UnitPrice|City 1|Arif|Keyboard|2|1500|Dhaka 2|Bina|Monitor|1|18000|Chattogram 3|Arif|Mouse|3|600|Dhaka 4|Chayan|Laptop|1|85000|Sylhet 5|Bina|Headphone|2|2500|Chattogram 6|Dipu|Monitor|2|17500|Dhaka @@end
Show solution
@@code sql the five queries (wrap each in $conn->query + while loop) -- 1 SELECT Customer, SUM(Qty * UnitPrice) AS TotalSpent FROM orders GROUP BY Customer ORDER BY TotalSpent DESC; -- 2 SELECT OrderID, Customer, Product, Qty * UnitPrice AS OrderValue FROM orders WHERE Qty * UnitPrice BETWEEN 3000 AND 40000; -- 3 UPDATE orders SET UnitPrice = UnitPrice * 1.05 WHERE Product = 'Monitor' AND City = 'Dhaka'; -- 4 SELECT City, SUM(Qty * UnitPrice) AS Revenue FROM orders GROUP BY City HAVING Revenue > 30000 ORDER BY Revenue DESC; -- 5 SELECT OrderID, Customer, Product, CASE WHEN Qty * UnitPrice >= 20000 THEN 'Big Order' ELSE 'Small Order' END AS Size FROM orders; @@end
