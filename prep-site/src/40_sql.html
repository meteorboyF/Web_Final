Databases, tables and rows

A database holds tables. A table is a grid: each column has a name and a type, and each row is one record. The primary key is the column that uniquely identifies a row (an ID).

Choose the type from the data

If the question’s table shows 24.00 or 4.5, use DECIMAL. If a later part multiplies by 1.10 (a 10% raise), an INT column rounds the result to a whole number. DECIMAL(10,2) keeps the cents.

ORDER BY and LIMIT

@@code sql SELECT * FROM book_info WHERE Category = 'Programming' ORDER BY Price DESC; -- highest first SELECT * FROM tourist_spot ORDER BY Rating DESC, SpotName ASC; -- tie-breaker SELECT * FROM sales_data ORDER BY Revenue DESC LIMIT 3; -- top 3 @@end

ASC (smallest first) is the default. Words like “most first”, “largest first”, “highest at the top”, “descending” all mean DESC.

Clause order (the instructor’s comment from the prep session) @@code sql SELECT columns | aggregation (SUM, AVG, COUNT) FROM table_name WHERE condition on individual rows (no aggregation) GROUP BY column(s) — "for each ..." HAVING condition on aggregation ORDER BY column DESC | ASC LIMIT n — top n results @@end

You must write them in this order. Swapping, say, ORDER BY before GROUP BY is a syntax error.

Aggregates, GROUP BY and HAVING

An aggregate squeezes many rows into one number. On its own it summarises the whole table:

@@code sql SELECT COUNT(*) FROM book_info; -- how many rows: 6 SELECT SUM(Price * Stock) AS NetWorth FROM book_info; -- 23650 SELECT AVG(Grade), MIN(Grade), MAX(Grade) FROM student_final; SELECT ROUND(AVG(Rating), 2) FROM tourist_spot; -- ROUND(x, 2) for tidy output @@end

GROUP BY = “for each …”

When the question says “for each course”, “per category”, “number of students who received each grade”, you GROUP BY that column. MySQL splits the rows into piles with the same value and runs the aggregate on each pile.

@@code sql SELECT LetterGrade, COUNT(*) AS Total FROM student_final GROUP BY LetterGrade; @@end
@@table rows before grouping | hl=2,5 LetterGrade|Grade B|85 A|92 C|78 D|65 A|95 B|80 @@end
@@table after GROUP BY LetterGrade LetterGrade|Total A|2 B|2 C|1 D|1 @@end
The GROUP BY rule

Every column in SELECT must be either the grouped column or inside an aggregate. SELECT StudentName, COUNT(*) … GROUP BY LetterGrade is wrong: which of the two A-students’ names would it show?

HAVING filters the groups

@@code sql SELECT Status, COUNT(*) AS Total FROM book_loans GROUP BY Status HAVING COUNT(*) > 1; -- drop groups with only one row @@end
WHERE

Filters rows before grouping. No aggregates allowed.

WHERE Category = 'Programming'

HAVING

Filters groups after grouping. Works with aggregates.

HAVING AVG(Rating) > 4.4

You can use both at once, and sort the groups:

@@code sql SELECT Category, COUNT(*) AS NumSpots, AVG(Rating) AS AvgRating, SUM(VisitorsPerYear) AS TotalVisitors FROM tourist_spot WHERE EntryFee > 0 -- 1. keep rows GROUP BY Category -- 2. make groups HAVING AVG(Rating) > 4.4 -- 3. keep groups ORDER BY AvgRating DESC; -- 4. sort (aliases are allowed here) @@end
Group by the name the question asks to display

“Display the course titles and the number of students” → GROUP BY CourseTitle. If IDs and names always match, grouping by CourseID, CourseTitle gives the same result.

UPDATE

@@code sql UPDATE table_name SET column = new_value WHERE condition; @@end
Never forget WHERE

Without a WHERE clause, every row is changed. (phpMyAdmin may refuse with “safe update mode”; your PHP won’t stop you.)

The four UPDATE shapes from past papers

@@code sql -- 1. Set a fixed value when conditions hold UPDATE student_final SET LetterGrade = 'C' WHERE Grade < 75 AND LetterGrade != 'D'; -- 2. Arithmetic, with a guard on the RESULT UPDATE student_final SET Grade = Grade + 5 WHERE Grade > 80 AND Grade + 5 <= 90; -- 3. Percentage change UPDATE sales_data SET Revenue = Revenue * 1.10 WHERE Revenue > 70000; -- +10% UPDATE book_info SET Price = Price * 0.90 WHERE Category = 'Language'; -- −10% -- 4. Several columns at once (comma-separated) UPDATE book_loans SET Status = 'Grace Period', PenaltyFee = 0 WHERE Status = 'Overdue' AND DaysOverdue < 7; @@end

UPDATE student_final SET Grade = Grade + 5 WHERE Grade > 80 AND Grade + 5 <= 90;

@@table checking each row (verified on MySQL 8) | hl=1 Name|Grade|Grade > 80?|Grade+5 ≤ 90?|Updated? Karim Uddin|85 → *90|yes|90 ✓|yes Rahim Ahmed|92|yes|97 ✗|no Jashim Hossain|78|no|—|no Jasica Ahmed|65|no|—|no Faria Karim|95|yes|100 ✗|no Niassoh Dihan|80|no (not strictly >)|—|no @@end
“only if the resulting value…”

That phrase always means a second condition on the new value: Grade + 5 <= 90, Salary + 5000 <= 60000, PenaltyFee * 1.10 <= 50.

Order matters

Run the parts in the order given. Each UPDATE changes the data the next query sees. In Spring 2026 Set A, the Heritage category only passes the “average rating > 4.4” test after part 2 raised Paharpur’s rating.

SQL · harder parts

CASE and subqueries

CASE: an if-else inside SQL

@@code sql SELECT StudentName, CASE WHEN Grade >= 90 THEN 'A' WHEN Grade >= 80 THEN 'B' ELSE 'C' END AS Computed FROM student_final; @@end

You can also do the labelling in PHP instead: fetch the row and use if. Both earn marks; the SQL way is shorter.

Subquery: compare with an average

@@code sql -- Products above the OVERALL average revenue (subquery runs once) SELECT ProductName, Revenue FROM sales_data WHERE Revenue > (SELECT AVG(Revenue) FROM sales_data); @@end

Correlated subquery: average of its own group

Summer 2025 asked for “Top Seller” if revenue is above the average of its own category. The inner query is linked to the outer row, so it’s re-run for each product:

@@code sql SELECT ProductName, CategoryName, CASE WHEN Revenue > (SELECT AVG(s2.Revenue) FROM sales_data s2 WHERE s2.CategoryID = s1.CategoryID) THEN 'Top Seller' ELSE 'Regular Seller' END AS Label FROM sales_data s1; @@end

s1 and s2 are aliases (nicknames) for the same table so the inner query can say “rows whose CategoryID equals this outer row’s CategoryID”.

The same thing with JOIN (alternative)

@@code sql SELECT s.ProductName, s.CategoryName, CASE WHEN s.Revenue > a.AvgRev THEN 'Top Seller' ELSE 'Regular Seller' END AS Label FROM sales_data s JOIN (SELECT CategoryID, AVG(Revenue) AS AvgRev FROM sales_data GROUP BY CategoryID) a ON s.CategoryID = a.CategoryID; @@end
Or do it in PHP (fallback if SQL gets tricky)

Run one query for averages per category, store them in a PHP array $avg[$row['CategoryID']] = $row['AvgRev'], then loop over all products and compare in PHP. Slower to write, but easy to reason about.

MySQL limitation

You can’t UPDATE a table using a subquery that reads the same table (Error 1093). If a question needs that, first SELECT the value into PHP, then put it into the UPDATE string.

Lesson from the PHP session

Writing $sql = "INSERT …"; does nothing on its own. The query only runs when you call $conn->query($sql). The instructor’s table stayed empty until he added that line.

PHP variables inside SQL strings

@@code php $name = $_POST["item-name"]; // text $count = (int) $_POST["item-count"]; // number // text values need single quotes INSIDE the SQL; numbers don't $sql = "INSERT INTO items (name, stock) VALUES ('$name', $count)"; $sql = "UPDATE items SET stock = stock - $count WHERE name = '$name' AND stock >= $count"; @@end
Beyond the exam: prepared statements

Pasting user input straight into SQL allows SQL injection. Real apps use $stmt = $conn->prepare("… WHERE name = ?"); $stmt->bind_param("s", $name); $stmt->execute();. The exam only uses fixed queries, so the simple form is fine there.

Error messages decoded
  • Unknown database: $dbname is spelled differently from what you created.
  • Table doesn’t exist: wrong table name, or the CREATE never ran.
  • Unknown column: column name typo, or text not quoted (WHERE Status = Overdue should be 'Overdue').
  • Call to a member function fetch_assoc() on bool: the SELECT failed. Print $conn->error to see why.
  • Undefined array key "Total": the alias in SQL doesn’t match the key in $row[…].
