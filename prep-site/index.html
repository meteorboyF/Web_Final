Rules from the course walkthrough

JS Question

Do not use a <form> tag. A form reloads the page on submit and wipes your JS variables.

Find elements with id (or class): document.getElementById("x").

PHP Question

Use <form action="file.php" method="post">.

PHP finds inputs by their name attribute: $_POST["x"].

SQL rule

Three kinds of query do not need to be in PHP: CREATE DATABASE, CREATE TABLE and INSERT. Write them wherever is easiest (ideally a .txt file, or run them in phpMyAdmin). SELECT and UPDATE queries go inside PHP code.

XAMPP and how to run your code

JavaScript runs inside the browser, so double-clicking index.html is enough. PHP is different: it runs on a server. The browser asks the server for a .php file, the server runs the PHP, and sends back only the HTML it printed. XAMPP gives you that server (Apache) and a database (MySQL / MariaDB) on your own machine.

BrowserRequestlocalhost/q2/index.html → you submit the form
ApacheRuns PHPq2/process.php reads $_POST and calculates
MySQLDataPHP sends SQL with $conn->query()
BrowserResponseOnly the echoed HTML comes back

Steps (from the PHP session’s howTo)

  1. Open the XAMPP Control Panel and Start both Apache and MySQL.
  2. Go to C:\xampp\htdocs (Mac: /Applications/XAMPP/xamppfiles/htdocs). Create one folder per question, e.g. q1, q2, q3, and open it in VS Code.
  3. Open pages through the server: http://localhost/q2/index.html. Opening a PHP file as file:///… shows the raw PHP source instead of running it.
  4. For the database, open http://localhost/phpmyadmin → SQL tab → paste your CREATE / INSERT queries → Go.
Common setup mistakes
  • MySQL won’t start → another MySQL is already using port 3306. Stop it, or change the port in XAMPP config.
  • Page downloads or shows code → you opened it with file://, not localhost.
  • “Unknown database” → the database name in new mysqli(…) doesn’t match what you created.
  • XAMPP defaults: user root, password "" (empty).

JS Question 1 · 10 marks

How JavaScript runs in a page

A JS exam answer is always two files: index.html (what the user sees) and script.js (what happens when they click). The HTML has three ingredients: inputs to type into, a button to click, and an empty output box (a div or label) that JS writes into.

Why the script goes last

The browser reads HTML top to bottom. If <script> were in the <head>, it would run before the button exists, so document.getElementById("addBtn") would return null and you’d get “Cannot read properties of null”.

No <form> tag in the JS question

A <button> inside a <form> submits the form and reloads the page. Every variable resets to 0, so the running total disappears. Keep inputs and button loose in the <body>.

Testing without HTML: the console

The Basic JS lecture practises in the browser console (right-click → Inspect → Console). prompt() reads input and console.log() prints. In the exam you’ll use HTML inputs instead, but console.log() is still your best debugging tool. Print a variable to see what it really holds.

JS

Variables, types and reading input

let and const

Use const for numbers the question fixes (“daily goal of 2000”, “weekly goal of 20 hours”). Use let for anything you add to. Avoid var; it works but has confusing scoping rules.

The #1 bug: input is always text

.value from an input, and prompt(), always give a string, even for type="number". With strings, + joins text instead of adding.

Try it · string vs number
Which one to use

Use Number() when hours or readings can be decimals (study hours, SpO2). Use parseInt() for counts and guesses. Both are accepted in the exam; just don’t forget to convert.

if / else if / else for ranges

Nearly every JS question asks for a feedback message “based on ranges”. Write the chain in order and let each else if assume the earlier checks failed:

Gaps in the ranges

Questions write ranges like “0–5, 6–12, 13–19”. Hours can be decimals (5.5 falls in no range!). Using <= 5, <= 12, <= 19 covers every value with no gaps.

Loops

In the exam you rarely need a loop for the main logic. The button click is the loop: each click runs your function once more. You might loop to build a list for display or to sum an array.

JS

Functions

Questions often say “Inside a function: …”. Either a named function called by the listener, or the anonymous listener function itself, satisfies that.

Pass the function, don’t call it

addEventListener("click", handleClick()) runs handleClick once immediately and gives the listener its return value (undefined). Write handleClick without parentheses.

Scope: why counters must be global

A variable declared inside a function is created fresh every time the function runs. To remember something between clicks (attempt count, running total, list of readings), declare it outside, at the top of script.js.

Try it · global vs local counter
global count = 0 · local count = 0
The local counter is declared inside the click function, so it restarts at 0 and only ever reaches 1.

Math

How the random formula works

Math.random() gives 0 ≤ r < 1. Multiply by the number of possible values (max − min + 1), floor it to get 0…(count−1), then shift up by min.

Rounding for display

toFixed(2) always shows 2 decimals (“96.00”). To drop pointless zeros, use Math.round(x * 100) / 100: 96 stays 96, 90.6666 becomes 90.67.

JS

The DOM: reading and writing the page

The DOM is the browser’s live model of your HTML. JS finds elements, reads what the user typed, and writes results back.

innerText

Shows exactly the characters you give it. "<br>" appears literally.

innerHTML

Parses tags. Use it when your output has line breaks (<br>) or bold text.

onclick in HTML: the other way

You may also see <button onclick="check()"> with function check(){…} in script.js. It works and is acceptable; the lecture prefers addEventListener because it keeps HTML and JS separate.

  • Every id in JS matches the HTML exactly (case-sensitive).

  • Input converted with Number() or parseInt().

PHP Question 2 · 10 marks

How PHP runs

PHP is a server-side language. Your browser never sees PHP code; it only sees what PHP echos. A PHP question is two files: an HTML form that collects numbers and a .php file that the form sends them to.

index.htmlForm<input name="students"> … user clicks Submit
HTTP POSTData travelsstudents=10&slices=3 sent to process.php
process.phpPHP runs$_POST["students"] → "10" → calculate
BrowserNew pageshows only the echoed text

Notice that the browser goes to a new page. That is why PHP doesn’t need global “memory” the way JS does: each submit is a fresh, one-shot calculation.

JS Q1

Runs in the browser · no form · find by id · page stays, values accumulate.

PHP Q2

Runs on the server · needs form · find by name · each submit is a new page.

PHP

Syntax, variables and echo

JS habits that break PHP
  • "a" + "b" in PHP tries to add numbers. Use "a" . "b".
  • Forgetting $ → “Undefined constant”.
  • Forgetting ; → “syntax error, unexpected …” on the next line.
  • "\n" doesn’t create a new line in the browser. Use <br>.
  • It’s elseif (one word) or else if. Both work in PHP.

Printing a tidy result table

Echoing HTML tags is allowed. A <table> or <br> lines are both fine for marks; a table looks closest to the sample outputs.

Is casting required?

PHP converts numeric strings automatically in maths ("10" * 3 is 30), so code without (int) usually still works. The lecture casts anyway: it’s safer, and examiners like seeing it.

Other form controls (shown in the prep session)

Optional: one file with isset()

You can put the form and PHP in the same .php file. Use isset() so the calculation only runs after submit. Two files is simpler and is what the solutions use.

Databases, tables and rows

A database holds tables. A table is a grid: each column has a name and a type, and each row is one record. The primary key is the column that uniquely identifies a row (an ID).

Data types you need

Choose the type from the data

If the question’s table shows 24.00 or 4.5, use DECIMAL. If a later part multiplies by 1.10 (a 10% raise), an INT column rounds the result to a whole number. DECIMAL(10,2) keeps the cents.

CREATE and INSERT (write these in a .txt / phpMyAdmin)

  • Text values go in single quotes: 'Karim Uddin'. Numbers don’t.
  • Commas between columns and between rows; no comma after the last one; ; at the end.
  • A name with an apostrophe needs it doubled: 'Cox''s Bazar Beach'.
  • You can skip the column list if you give a value for every column in order.

ORDER BY and LIMIT

ASC (smallest first) is the default. Words like “most first”, “largest first”, “highest at the top”, “descending” all mean DESC.

Clause order (the instructor’s comment from the prep session)

You must write them in this order. Swapping, say, ORDER BY before GROUP BY is a syntax error.

The GROUP BY rule

Every column in SELECT must be either the grouped column or inside an aggregate. SELECT StudentName, COUNT(*) … GROUP BY LetterGrade is wrong: which of the two A-students’ names would it show?

HAVING filters the groups

WHERE

Filters rows before grouping. No aggregates allowed.

WHERE Category = 'Programming'

HAVING

Filters groups after grouping. Works with aggregates.

HAVING AVG(Rating) > 4.4

Group by the name the question asks to display

“Display the course titles and the number of students” → GROUP BY CourseTitle. If IDs and names always match, grouping by CourseID, CourseTitle gives the same result.

“only if the resulting value…”

That phrase always means a second condition on the new value: Grade + 5 <= 90, Salary + 5000 <= 60000, PenaltyFee * 1.10 <= 50.

Order matters

Run the parts in the order given. Each UPDATE changes the data the next query sees. In Spring 2026 Set A, the Heritage category only passes the “average rating > 4.4” test after part 2 raised Paharpur’s rating.

MySQL limitation

You can’t UPDATE a table using a subquery that reads the same table (Error 1093). If a question needs that, first SELECT the value into PHP, then put it into the UPDATE string.

SQL PHP · memorise this

Running SQL from PHP with mysqli

The exam’s own “Sample SQL Query” box (Spring 2025 paper) gives this exact shape. The connection code earns marks even if a query is wrong, so always write it.

  • $conn->query($sql) sends the SQL. For SELECT it returns a result set.
  • $result->num_rows is how many rows came back.
  • fetch_assoc() gives the next row as an array keyed by column name, and null when there are no more rows, which ends the while.
  • The key is the column name as it appears in the result. If you wrote COUNT(*) AS Total, use $row["Total"]. Without an alias it would be $row["COUNT(*)"], so always alias aggregates.
Lesson from the PHP session

Writing $sql = "INSERT …"; does nothing on its own. The query only runs when you call $conn->query($sql). The instructor’s table stayed empty until he added that line.

PHP variables inside SQL strings

Beyond the exam: prepared statements

Pasting user input straight into SQL allows SQL injection. Real apps use $stmt = $conn->prepare("… WHERE name = ?"); $stmt->bind_param("s", $name); $stmt->execute();. The exam only uses fixed queries, so the simple form is fine there.

Error messages decoded
  • Unknown database: $dbname is spelled differently from what you created.
  • Table doesn’t exist: wrong table name, or the CREATE never ran.
  • Unknown column: column name typo, or text not quoted (WHERE Status = Overdue should be 'Overdue').
  • Call to a member function fetch_assoc() on bool: the SELECT failed. Print $conn->error to see why.
  • Undefined array key "Total": the alias in SQL doesn’t match the key in $row[…].

One-page cheatsheet

JS · Q1

No <form>. Script at the bottom of body. Globals outside the function. Math.floor(Math.random()*(max-min+1))+min. /[A-Z]/.test(s). Math.abs().

PHP · Q2

$ on every variable. . joins strings. name ↔ $_POST["name"]. Best 2 of 3 = sum − min().

SQL + PHP · Q3
Words → SQL
  • “for each / per X” → GROUP BY X
  • “number of” → COUNT(*) · “total” → SUM() · “average” → AVG()
  • “only groups with …” → HAVING
  • “most / largest first” → ORDER BY … DESC
  • “top 3” → LIMIT 3
  • “contains X” → LIKE '%X%' · “between a and b (inclusive)” → BETWEEN
  • “only if the result …” → extra AND on the new value
  • “label A or B” → CASE WHEN … THEN … ELSE … END
  • “above its own group’s average” → correlated subquery
Before handing in
  • Ran the first sample row through by hand?
  • Every UPDATE has a WHERE?
  • Text in 'quotes' inside SQL?
  • Aggregates have an AS alias that matches $row["…"]?
  • Parts run in the order given?
  • CREATE / INSERT written in the txt file?
  • JS ids and PHP names match the HTML exactly?
